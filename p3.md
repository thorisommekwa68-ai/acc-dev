# AQUA CAPRICORN CREATIVES — BOS REDEVELOPMENT MASTER BRIEF

## Project objective

Complete the redevelopment of the existing Aqua Capricorn Creatives Business Operating System (BOS) in the GitHub repository:

https://github.com/thorisommekwa68-ai/acc-dev

The objective is to transform the existing BOS into a premium, integrated business management platform with a complete redesign, hybrid visual direction and all existing and planned modules.

## 1. Existing technology

Preserve the current technology stack unless a change is justified and explicitly approved:

- HTML
- CSS
- Vanilla JavaScript
- Supabase Authentication
- Supabase PostgreSQL
- Supabase Row Level Security
- Cloudflare Pages hosting

Important existing files:

- WEBSITE/index.html
- WEBSITE/app.js
- WEBSITE/styles.css
- WEBSITE/supabase-config.js
- WEBSITE/service.html
- WEBSITE/service.js
- WEBSITE/supabase/migrations/

## 2. Mandatory preservation requirements

Before modifying any code:

1. Inspect the complete repository.
2. Understand all existing application functions and event handlers.
3. Document all existing data structures and Supabase interactions.
4. Inspect the SQL migration and current RLS policies.
5. Identify all dependencies between the BOS and public services website.
6. Create a separate development branch.
7. Keep the main branch unchanged until the new version has passed testing.

Do not delete, overwrite or recreate existing Supabase records.

Do not expose the Supabase service-role key.

Do not remove founder authentication restrictions or weaken RLS policies.

Do not break the public services page or its enquiry submission workflow.

## 6. Business workflow

Design around the following lifecycle:

Enquiry → Qualification → Quotation → Accepted Project → Tasks → Deliverables → Invoice → Payment.

Ensure that the modules share consistent records and relationships.

## 7. Financial accuracy

Distinguish between:

- Accepted project value
- Pending quotation value
- Invoices issued
- Payments received
- Outstanding invoice balances
- Expenses
- Net cash position

Do not represent accepted project value as cash received.

Do not calculate outstanding balances from assumptions.

Every financial KPI must have a traceable calculation and source records.

## 8. Founder workspace

The BOS must support the two existing founders while retaining the existing authorised-account restrictions.

Each founder should have:
- Personal dashboard.
- Assigned tasks.
- Upcoming meetings.
- Relevant project responsibilities.
- Notifications.
- Shared business overview.

Do not introduce public registration or weaken existing access restrictions.

## 9. Engineering requirements

- Keep the frontend modular and maintainable.
- Separate presentation from business logic where practical.
- Use reusable components and consistent rendering patterns.
- Validate user input.
- Handle loading, error and empty states.
- Prevent duplicate submissions.
- Preserve Supabase authentication and session handling.
- Preserve existing data compatibility.
- Introduce database changes only through reviewed, additive migrations.
- Keep secrets out of frontend code.

## 10. Quality assurance

Test:
- Authentication and authorisation.
- Existing records and CRUD operations.
- Public enquiry submissions.
- Navigation and module rendering.
- Personal task filtering.
- Financial calculations.
- Forms and validation.
- Responsive layouts.
- Supabase RLS.
- Production build and deployment.

## 11. Delivery rules

Do not deploy incomplete work.

Do not modify production directly.

Do not silently remove existing functionality.

After each development phase, provide:
- Files changed.
- Functionality completed.
- Tests performed.
- Known issues.
- Deployment implications.

The final result must be a complete, working Aqua Capricorn Creatives Business Operating System, not merely a static dashboard mock-up.
